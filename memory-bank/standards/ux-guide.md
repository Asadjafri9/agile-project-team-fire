# UX Guide

## Overview

Use the project's existing visual language and component conventions. See [requirements.md](../../requirements.md) for user journeys and accessibility acceptance criteria.

## Interaction

- Board and backlog controls need keyboard operation, visible focus, labels, and status cues that do not rely on color alone.
- Keep loading, empty, validation, and conflict states understandable to team members.
- A hidden control is a usability choice, not an authorization boundary.

## Scope

The frontend owner makes feature UI changes on `fe/*` branches. This guide does not grant Systems ownership of frontend code.
